# AirTalk 화면 문구 규칙

원칙: **사용자가 당장 알아야 할 정보만, 필요한 순간에.** 개발·운영 설명(AGC, 네이티브 캡처, 서버 주소 사정, 모델 이름 등)은 일반 화면에 쓰지 않는다.

## 종류별

- **버튼·상태 알림**: 짧게 한 문장, 완료 사실만.
  - 예) "참가자의 번역 음성 재생을 켰습니다." (부연 설명 X)
- **오류**: 원인 + 해결 방법, 최대 두 문장.
  - 예) "마이크를 사용할 수 없습니다. 마이크 권한을 허용한 뒤 다시 시도하세요."
- **삭제·계정 확인 창**: 데이터 손실 여부를 꼭 적는다.
  - 예) "'{이름}' 세션과 대화 기록이 모두 삭제되며 되돌릴 수 없습니다."
- **고급 설정**: 전문 용어는 허용하되 필요한 설명만. 진단 정보는 일반 사용자 화면에 두지 않는다.
- **사용자가 직접 해결해야 하는 곳**(장치 연결, 권한 오류)은 조금 길어도 구체적으로. 단순 상태 변경은 짧게.
- **빈 화면**: 다음 행동 한 줄. 예) "시작 버튼을 눌러 번역을 시작하세요."

## 말투

- 앱·관리 화면: 편안한 존댓말 — "~하세요 / ~했습니다".
- 외부 참가자가 보는 화면(QR 뷰어 등): 부드러운 존댓말 — "~해요 / ~해 주세요".

## 용어·표기 통일

- "시작 버튼을 누르세요" (대괄호 [시작] X)
- "이 기기" (폰 X), "번역 서비스" (엔진 X), "시스템 오디오" (PC 소리 X), "입력 소스", "입력 장치"
- 줄표(—) 대신 마침표로 문장을 나눈다.
- 영어·일본어는 한국어를 먼저 확정한 뒤 같은 뜻으로 번역한다(문구 표 한 곳에 ko/en/ja 를 나란히).

## 숫자·시간

- 경과 시간 `03:12`(tabular), 인원 "뷰어 3명", 백분율 "100%".
